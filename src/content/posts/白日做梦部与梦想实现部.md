# 白日做梦部与梦想实现部

如果要给我自己的做事方式打个比方，我觉得我脑子里常年开着两个部门。

一个叫 **白日做梦部**，一个叫 **梦想实现部**。

### 白日做梦部

白日做梦部的工作内容很简单：负责想，负责狂想，负责在洗澡的时候、走路的时候、写代码写到一半走神的时候，突然冒出一个念头然后迅速把它放大成一部完整的电影。

这个部门的 KPI 就是胡说八道。能不能做不重要，难度多大不重要，现阶段自己有没有那个能力也不重要。重要的只有一个：这个想法够不够让我兴奋。

比如看到一段 Blender 建模视频，脑子里立刻就开始放片了——"那我能不能做一个赛博朋克风格的短片？主角是个机械忍者，场景是雨夜霓虹灯笼罩的街道……"连分镜都想好了，配乐都想好了，甚至连发布之后大家会怎么夸我都想好了。

比如学完 UE5 基础操作，白日做梦部马上加班："第三人称跑酷已经不够看了，下一步直接做开放世界吧。地图要大，NPC 要智能，剧情要分支，战斗系统要有打击感……"

比如期末复习到半夜，白日做梦部突然插嘴："我们组个团队做独立游戏吧，名字我都想好了。"

这就是白日做梦部的日常。它不管现实，只管想象力。它是那种会在你焦头烂额的时候突然递给你一张蓝图然后说"看看这个，是不是挺酷的"的人。

以前我其实有点烦它。因为想的东西太多了，实现的没几个，总会觉得自己在浪费时间。但后来我慢慢发现，白日做梦部其实很重要。它是我所有动力的起点——如果连想都不敢想，那连开始的机会都没有。

### 梦想实现部

如果说白日做梦部负责点火，那梦想实现部负责的就是别让火烧一下就灭了。

这个部门的工作风格和白日做梦部完全不同。它务实、冷静、甚至有点扫兴。白日做梦部说"我们做开放世界吧"，梦想实现部说"先把第三人称跑酷的关卡搭完"。白日做梦部说"我们要做独立游戏"，梦想实现部说"先把需求文档写出来，代码仓库建起来，技术栈定下来"。

它不负责浪漫，它负责落地。

但正是因为有梦想实现部的存在，我才不是那个"只会说不会做"的人。那些被白日做梦部抛出来的想法，经过梦想实现部的筛选和打磨，总有一些能变成真正能跑起来的东西。

比如那 3 个 Blender 短片。白日做梦部看完教程之后就开始画饼，什么风格、什么氛围、什么镜头语言都想好了；但真正让它们从一个模糊的画面变成渲染出来的成片，靠的是梦想实现部一点一点跟着教程做，一个面一个面地调，一帧一帧地渲染。

比如第三人称跑酷和 FPS。白日做梦部想的是"我要做个很酷的游戏"，梦想实现部想的是"平台间距设多少米玩家跳起来最舒服""射击反馈延迟控制在多少毫秒手感最好"。

比如和舍友一起做的项目。白日做梦部负责在讨论的时候说"我们这个项目可以加点这个、加点那个"，梦想实现部负责回去写代码、调 bug、对接口、然后默默把功能推上去。

### 两个部门的协作

这两个部门看起来风格对立，但其实谁也离不开谁。

没有白日做梦部，梦想实现部就会变成一个纯粹的干活机器，做出来的东西虽然能跑，但没有灵魂。一个人如果从来不敢想大的东西，那他做的事情就会越来越小、越来越保守，最后可能连自己为什么在做这件事都忘了。

没有梦想实现部，白日做梦部只会产出越来越多没有下文的空想，想法越攒越多，焦虑越攒越多，最后变成了那种"我有很多想法但是什么都没做出来"的人。光想不做的最大代价不是没成果，而是人会慢慢不相信自己。

所以我现在的状态是：允许白日做梦部随时开工，随便画饼，爱想什么想什么；但也会让梦想实现部在场，安静听完，然后挑一个最值得做的，开始干活。

两个部门打架的时候，我也学会了调停。白日做梦部说"一步到位"，梦想实现部说"先做最小可行版本"。最后折中，先做一个能跑的东西出来，然后在这个基础上慢慢加。事实证明，这条折中路线最有效。

### 写在最后

其实回头看，我做的很多事都是这么过来的。从学 C++ 到学算法，从学 Java 到做项目，从学 Blender 到出短片，从学 UE5 到做出第一个能玩的游戏——每一次都是白日做梦部先跳出来说"这个好酷我也想试试"，然后梦想实现部接过话头说"行，那就从最基础的部分开始"。

我想，大概每个人脑子里都有这样两个部门吧。差别只在于，有的人白日做梦部被自己关掉了，觉得想太多不切实际；有的人梦想实现部长期休眠，想了很多但从来没动过手。

而我比较幸运的是，这两个部门都还在正常运转。白日做梦部每天都在给我画新饼，梦想实现部每天都在提醒我还有哪些饼没烙完。

这种感觉挺好的。
