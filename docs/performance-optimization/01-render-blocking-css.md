# 01：减少渲染阻塞 CSS

## 问题

Lighthouse 报告显示，页面初始渲染前需要等待 6 个 CSS 请求完成，预计优化后可缩短约 `1,710 ms`。这些请求合计约 `49.9 KiB`，其中两个 `_page_.*.css` 文件占大部分体积。

报告中同时出现 `friends.*.css`、`about.*.css` 和 `photoswipe.*.css`。这提示我们应检查当前页面是否加载了与首屏无关的路由或组件样式；它是排查线索，不直接等同于根因。

完整的截图基线见[专题首页](./README.md)。

## 目标

- 减少首屏必须下载和解析的非关键 CSS。
- 降低 Lighthouse「渲染阻塞请求」中的预计节省时间。
- 改善 LCP，同时不引入无样式内容闪烁、布局偏移或交互回归。

## 定位步骤

1. 使用生产构建复现问题，记录被测 URL、设备模拟、网络和 CPU 节流条件。
2. 查看被测页面最终 HTML 中的 `<link rel="stylesheet">`，将每个生成文件追溯到源码入口。
3. 检查公共布局是否静态引入了只在特定页面使用的组件和样式。
4. 检查 `about`、`friends`、图库/PhotoSwipe 等样式是否在无关页面进入首屏依赖链。
5. 使用浏览器 Coverage 或等效工具确认首屏未使用 CSS 的比例，再决定拆分边界。

## 根因

`src/components/misc/ImageWrapper.astro` 原先使用 `import.meta.glob("../../**")` 寻找本地图片。这个模式匹配了整个 `src`，不仅包含图片，也包含所有页面、CSS 和脚本。由于 `ImageWrapper` 位于公共布局依赖链中，Astro/Vite 最终将首页、归档、关于、友链以及 PhotoSwipe 的样式全部关联到每个页面。

构建依赖追踪确认，截图中的 6 个 CSS 请求正是由该依赖图产生，而不是 Swup 的 `updateHead` 配置造成。

## 已实施

- 将图片 glob 收窄为 `avif/gif/jpeg/jpg/png/svg/webp` 文件。
- 在公共布局中显式加载基础样式、滚动条样式、页面过渡和主题变量。
- 将 Markdown、代码块和 Markdown 扩展样式放回 `Markdown.astro`，只由相关页面加载。
- 将 PhotoSwipe 基础样式和主题样式改为 `?inline` 动态模块，只在页面存在可放大图片时注入。
- 将 Roboto 的 400、500、700 字重从全字符集 CSS 改为 Latin 子集 CSS；中文继续使用系统回退字体。
- 清理重复的 PostCSS Tailwind/Nesting 注册，保留 Astro Tailwind 集成提供的处理链。

## 候选方案

按定位结果选择，不预先把所有方案同时应用：

- 将路由专属样式留在对应页面或组件中，避免由全局布局统一引入。
- 对首屏之外才出现的重型组件做按需加载，同时拆分它们的样式依赖。
- 删除重复规则和已经不再使用的样式。
- 只在证明确有收益时提取或内联少量关键 CSS；需要同时评估缓存、HTML 体积和维护成本。
- 不为消除审计提示而简单异步加载全部样式，这会带来无样式内容闪烁和布局偏移。
