# 02：定位并减少强制自动重排

## 问题

Lighthouse 将「强制自动重排」标记为待优化项。当前截图没有展开具体调用栈、耗时和触发次数，因此还不能判断是哪段代码导致，也不能把问题直接归因于某个动画或组件。

## 目标

- 找到触发布局同步计算的实际调用栈和交互场景。
- 减少单帧内交错的 DOM 写入与布局读取。
- 在不改变现有视觉效果和交互行为的前提下减少主线程阻塞。

## 取证步骤

1. 使用生产构建复现，并在浏览器 Performance 面板录制页面加载、滚动、点击和页面切换。
2. 在时间线中定位 Layout/Recalculate Style 事件，保存最长事件的调用栈和耗时。
3. 区分「页面正常布局」与「JavaScript 写入样式后立即读取布局」造成的同步重排。
4. 重点检查高频事件中的布局读取，例如 `getBoundingClientRect()`、`offsetWidth`、`offsetHeight`、`scrollTop` 和 `getComputedStyle()`。
5. 记录触发页面、操作步骤、调用文件和行号，之后再选择修复方式。

## 候选方案

- 将同一帧内的布局读取集中在 DOM 写入之前，缓存不会立刻变化的测量结果。
- 将连续的视觉更新合并到 `requestAnimationFrame`，避免每个输入事件都直接修改布局。
- 动画优先使用 `transform` 和 `opacity`，避免频繁修改会触发布局的几何属性。
- 对滚动、指针移动和尺寸变化处理设置与体验相符的采样或节流策略。
- 缩小受影响的 DOM 范围；只有在确认不会破坏布局时才考虑 CSS containment。

## 代码定位与实施

本轮静态检查找到了三处明确的高频布局风险：

1. `Layout.astro` 的滚动处理会在修改 class 后再次读取 `scrollTop`、视口尺寸和阈值。
2. `TOC.astro` 会先切换目录项 class，再立即调用 `getBoundingClientRect()`、`clientHeight` 和 `offsetTop`。
3. 公共布局会在首屏同步初始化 OverlayScrollbars，对 `body` 进行运行时包装和测量。

对应调整：

- 滚动和尺寸变化事件改为用 `requestAnimationFrame` 合并，同一帧只读取一次 `scrollY` 和视口尺寸，然后统一切换 class。
- TOC 更新改为先计算活动范围并完成全部布局测量，之后再统一更新 class、指示器和滚动位置；连续观察回调会合并到一个动画帧。
- 删除 OverlayScrollbars 的首屏初始化和依赖，改用 CSS 原生滚动条；KaTeX 直接使用 CSS 横向滚动，不再运行时包裹 DOM。
- 鼠标特效改为仅在存在波纹、粒子或轨迹时请求下一帧，空闲状态不再持续运行 60 FPS 循环。
